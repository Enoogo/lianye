# 连页：手动悬浮控制与必要反馈

2026-10-07 更新：下文首次指导「接上新内容后全部收起」的规则已由 [渐进式滑动指导](2026-10-07-lianye-progressive-swipe-guide-design.md) 替代。当前原型为 V5，其余会话控制与反馈规则沿用本稿。

用户已认可三个独立 agent 审查后的修正，并要求继续。此稿替代 V3 中“进入目标页面开始、返回连页结束”的手动交互；名称、Logo 01、自动路径、共同结果页和六类厂商帮助沿用现状。本次交付可点击原型，系统授权与图像采集仍为模拟。

## 状态与提示

本次屏幕捕获授权完成后进入待开始。普通悬浮控制可用时，打开目标页面后显示“开始”，旁边提示“打开要截的页面，点「开始」”，点击后收起。准备阶段能直接取消。打开目标页面、浏览或停留不会开始追加长图。

点开始后显示“正在截取”；第一张有效画面到达后才显示“已截 1 屏”和“结束”。首次使用附“每次向上滑半屏，稍停；截完点结束”，首次成功追加新内容后收起，并在下一次任务保持已学会状态。日常常驻信息仅为有效屏数与结束动作。正常停留、重复和回滑不增长数字，不弹提醒。

确认没有接续成功时冻结有效内容，立即显示“未能接上，已保留前段”，保留结束入口；不把失败统一归责为滑动过快，也不承诺往回滑即可恢复。点结束先收尾已经到达的有效内容，再停止追加并生成共同预览。有一屏即可正常完成；尚无有效画面则返回并显示“还未截到画面”，不虚构草稿。首屏失败就地重试或取消。

系统中断或重新挂载后结束旧授权会话，保留有效草稿并显示“截图已中断，已保留 N 屏”；不恢复正在运行的捕获。再次开始必须重新授权。

## 控制入口与视觉

手动悬浮能力与无障碍开关独立。控件靠边、可拖动，提示随控件移动且不能超出屏幕，触控目标至少 44 px。反馈不靠持续闪烁和每屏震动。新增有效屏数短暂强调，照顾减少动态效果的系统设置。

普通悬浮窗不可用且通知可见时，在系统通知栏提供相同开始、状态和结束动作。两者都不可用时留在准备阶段，解释“需要悬浮球或通知来开始和结束”，只在该分支提供开启入口，不能先把用户送去目标 App。原型增加通知兜底、控制未开启、首屏失败和系统中断情境，以便检查这些分支；情境选择器位于产品外。

手动帮助更新为授权、在目标页面点开始后自己滑动并点结束、检查保存三个步骤；自动帮助中的厂商路径继续按需展开。

## 边界与验证

当前示例以稳定滚动及缺少重叠的跳跃模拟新增内容与缺口，不是图像匹配算法。计数表达成功追加的模拟画面，不表达原始采样次数。系统通知栏、普通悬浮授权和系统终止均为模拟；没有给手机开启新权限，没有修改 Android 捕获服务。

Android 实施仍须验证普通悬浮控件从图片中排除、单 App 共享、通知面板与返回过渡画面的过滤、不同厂商权限和最后一帧收尾。悬浮控制应随会话显示，不依赖自动识别任意目标页面；原型只在示例目标页面绘制控制。通知授权之外还须确认应用通知及截图通知渠道可见。Android 13 拒绝通知后前台服务通知不出现在通知栏；MediaProjection 会话被停止后重新授权。参考 https://developer.android.com/develop/ui/compose/notifications/notification-permission#exemptions 与 https://developer.android.com/media/grow/media-projection 。

验收覆盖明确开始、首屏真实反馈、教学出现与收起、有效进度、缺口即时可见、取消与首屏失败、结束前待处理滚动的收尾、通知入口与双入口不可用、系统中断和草稿恢复、320/390/736 px 与深色，以及已有自动流程和保存竞态回归。

V4 完成原型验收：25 项状态/OEM 测试、98 项原自动、77 项手动和 10 项宿主检查通过；保存竞态回归通过，浏览器无 JS 异常。已查看最新六屏总览、通知、控制阻塞、中断、窄屏拖动和深色错误截图。三个独立 agent 的复核必修项已落实：桌面明确悬浮按钮所在场景；首屏提前结束等待原回调；通知入口用状态栏模拟下拉；悬浮授权使用系统设置页。测试仅证明上述模拟流程与布局。
