# 手动长截图匹配与恢复

用户已批准修复实际滚动区域匹配和暂时失败后的继续观察。继续使用同一悬浮球，不增加用户选项。

## 已确认的问题

生产手动会话在两次无法匹配后冻结采样；手机当前会话确实停在 GAP。匹配器仅排除顶部 10%、底部 12%，对剩余像素求全局均值。超过这些比例的固定导航和局部视频变化会破坏正确重叠评分。

实机进一步复现了取帧缓存中的控件残影、折叠导航栏边界误差、半透明底栏重复，以及隐藏控件时点击穿透。这些问题一并纳入本次修复。

## 行为

- 匹配同一画面的静止边缘，识别实际固定顶部和底部，比较两帧共有的滚动内容。
- 对局部动态画面使用分块一致性；必须有足够分散的独特内容证明位移。纯周期卡片和无重叠不能凭估计拼接。
- 将静止位置与局部动画分开判断；用相邻静止样本的变化区域排除视频、加载徽标。排除后仍要求至少相当于视口十分之一的有效像素，并验证独特标题没有冲突。
- 隐藏控件后排空中间缓存，并等待新的显示缓冲区；保留透明点击区域，使结束按钮不会穿透到目标应用。
- 使用可靠重叠的下边界辅助确定固定底栏范围，避免半透明底栏在增量中重复。
- 暂未接上时保持上次可靠画面为锚点，继续采样，不写入失败画面、不增加进度。恢复可靠重叠后自动续接并恢复滑动指引。
- 用简短提示说明暂停并向下滑回一点；结束始终可用。若仍未恢复，结束只保留可靠前段并标记未完全接上。
- 已有捕获先结束并备份，测试结束恢复用户草稿和权限状态。正式版及数据不动。

## 验收

固定大导航、局部动态视频、重复内容唯一标题、真正歧义、回滑和不连续画面恢复均有回归测试。手机验证普通列表、动态列表、失败恢复、连续多次捕获以及自动模式入口。原始用户画面仅留在忽略的 build 目录，不进入测试资源。
